## 1. 文档目的

本文档用于定义 SureGrad Android MVP 的产品范围、用户流程、页面清单、功能规则、异常场景与验收边界，供后续设计、前端、后端、数据和测试工作直接使用。

本阶段目标不是做“全能考研平台”，而是优先验证以下核心闭环：

`查院校 -> 收藏对比 -> 设定目标 -> 生成学习计划 -> 执行 Todo -> 打卡复盘`

## 2. 产品定义

### 2.1 产品名称

- 中文名：`一研为定`
- 英文名：`SureGrad`

### 2.2 产品定位

SureGrad 是一款面向考研学子的 Android 备考助手，聚焦于：

1. 院校与专业信息查询
2. 分数线、报录比、复录比等择校决策支持
3. 学习路线、周计划、日计划与 Todo 执行
4. 合法公开学习资料推荐

### 2.3 MVP 目标

MVP 只解决两个关键问题：

1. 帮用户快速完成择校决策
2. 帮用户把备考目标落到日常执行

## 3. 目标用户

### 3.1 目标人群

1. 大三 / 大四考研用户
2. 二战、三战考生
3. 在职备考用户

### 3.2 典型用户画像

#### 用户画像 A：择校焦虑型

- 不知道考哪里
- 想看分数线、报录比、复录比
- 希望有收藏和对比能力

#### 用户画像 B：执行薄弱型

- 有目标院校，但计划不稳定
- 常常列计划但无法持续执行
- 需要明确节奏和每日任务管理

#### 用户画像 C：资料筛选型

- 不清楚当前阶段该看什么课、什么书
- 害怕被低质量或侵权资源误导
- 需要按科目和阶段的推荐资源

## 4. 产品目标与指标

### 4.1 用户目标

1. 让用户在 10 分钟内完成院校检索和初步筛选
2. 让用户在首次使用中完成目标设置和学习计划创建
3. 让用户形成日常 Todo 和打卡习惯

### 4.2 业务目标

1. 建立可持续维护的院校数据展示能力
2. 建立可复用的学习计划和执行工具基础
3. 为后续版本扩展 AI、复试、调剂、会员服务预留结构

### 4.3 MVP 核心指标

1. 新用户目标设置完成率
2. 学习计划创建率
3. 院校收藏率
4. 对比页使用率
5. Todo 创建率
6. 日活用户打卡率
7. 7 日留存

1. 优先闭环，不优先花哨功能
2. 优先官方数据展示，不优先UGC内容
3. 优先执行工具，不优先内容社区

## 6. 核心用户流程

### 6.1 新用户主流程

1. 用户打开 App
2. 浏览引导页
3. 登录 / 跳过登录进入体验
4. 设置备考年份、身份、目标专业方向、可投入时间
5. 进入择校页查看院校信息
6. 收藏 1-3 个目标院校并发起对比
7. 确定目标院校 / 专业
8. 生成学习路线模板
9. 查看本周计划和今日 Todo
10. 完成打卡并查看统计

补充说明：

1. 用户首次登录后优先完成基础档案，目标院校允许暂时为空；若未确定目标院校，则继续进入择校流程完成收藏、对比和目标确认。
2. 用户选择跳过登录时，默认进入择校页体验；当用户在收藏、对比、设目标、生成计划、Todo、打卡等动作中触发登录时，登录成功后应返回原触发页面继续操作。

### 6.2 回访用户主流程

1. 打开首页
2. 查看今日待办和倒计时
3. 完成 Todo
4. 学习后打卡
5. 查看学习统计
6. 必要时回到择校或资料页继续查询

## 8. 功能需求明细

## 8.1 账号与用户基础档案

### 功能目标

支持用户建立基础备考身份，并保存个性化规划所需信息。

### 功能说明

1. 支持手机号登录或验证码登录
2. 支持游客浏览部分内容
3. 首次登录后引导填写基础档案

### 基础档案字段

1. 备考年份
2. 当前身份：应届 / 二战 / 在职
3. 本科专业
4. 意向专业方向
5. 每日可投入学习时长
6. 是否考数学
7. 当前目标院校，可为空

### 业务规则

1. 未登录用户可浏览院校列表和部分资料
2. 收藏、对比、计划、Todo、打卡必须登录
3. 首次未完成档案时，首页和规划页需提示补全
4. 首次登录后仅强制填写必填基础档案字段即可继续，非必填信息允许后续补充

### 异常场景

1. 验证码发送失败时提示重试
2. 网络异常时保留已填写内容
3. 用户跳过目标院校时，后续允许在择校页重新补设

## 8.2 择校列表页

### 功能目标

帮助用户快速查找和筛选目标院校及专业。

### 页面内容

1. 搜索框
2. 筛选项
3. 院校列表卡片
4. 最近浏览入口
5. 我的收藏入口

### 筛选项

1. 地区
2. 学校层次
3. 专业门类
4. 学硕 / 专硕
5. 是否考数学
6. 备考年份

### 列表卡片字段

1. 学校名称
2. 所在城市
3. 目标专业或热门专业
4. 最近年份分数线摘要
5. 报录比摘要
6. 收藏按钮

### 业务规则

1. 默认按综合热度或推荐排序
2. 搜索支持学校名、院系名、专业关键词
3. 用户筛选后应保留条件直到主动清空

### 异常场景

1. 无结果时展示空态和建议筛选
2. 数据缺失时字段显示“待补充”

## 8.3 院校详情页

### 功能目标

让用户基于结构化数据完成择校判断。

### 页面模块

1. 学校基础信息
2. 招生信息
3. 分数线趋势
4. 报录比 / 复录比
5. 初试科目
6. 参考书目
7. 官方链接
8. 收藏按钮
9. 查看专业列表并选择对比项

### 展示字段

1. 学校名称、城市、院系、专业
2. 学制、学费
3. 招生人数
4. 推免人数或说明
5. 历年分数线
6. 报录比
7. 复录比
8. 初试科目
9. 参考书
10. 数据更新时间
11. 数据来源入口

### 业务规则

1. 所有关键数据应展示对应年份
2. 数据缺失时要明确标记，不得用空白替代
3. 页面需注明“以官方最新公告为准”

### 异常场景

1. 某年份无数据时展示“暂无该年份数据”
2. 官方链接失效时展示“链接待更新”

## 8.4 专业详情页

### 功能目标

从专业维度补充院校详情的细粒度信息。

### 页面内容

1. 专业名称与代码
2. 所属院校与院系
3. 学硕 / 专硕
4. 初试科目
5. 参考书
6. 历年分数线
7. 报录比 / 复录比
8. 适合人群说明

### 业务规则

1. 专业详情可从院校详情跳转
2. 若同校多研究方向，需展示研究方向列表

## 8.5 收藏与对比

### 功能目标

帮助用户缩小选择范围，完成目标决策。

### 功能说明

1. 支持收藏院校
2. 支持收藏专业
3. 支持收藏资料
4. 支持将专业加入对比
5. 支持查看我的收藏

### 对比维度

1. 分数线
2. 报录比
3. 复录比
4. 招生人数
5. 学费
6. 所在城市
7. 初试科目

### 业务规则

1. MVP 对比以专业粒度为准，对比项代表具体的学校 + 院系 + 专业组合
2. 对比数量建议限制为 2-4 项
3. 重复加入对比时提示已存在
4. 未登录不可使用收藏和对比

### 异常场景

1. 超出对比数量限制时提示先移除
2. 某些字段缺失时仍允许对比，但需标记缺失

## 8.6 目标设置与学习路线

### 功能目标

将择校信息转化为执行型学习方案。

### 功能说明

1. 用户选择目标院校和目标专业
2. 用户输入可投入时长与基础情况
3. 系统生成学习路线模板

### 路线模板类型

1. 标准备考版
2. 基础薄弱版
3. 跨考版
4. 在职版

### 路线展示内容

1. 全年阶段划分
2. 各阶段目标
3. 科目建议重心
4. 周计划建议
5. 冲刺提醒

### 业务规则

1. MVP 阶段采用规则模板生成，不做 AI 个性化生成
2. 用户可二次编辑计划强度和时间分配
3. 用户变更目标院校后可重新生成计划
4. 在目标院校暂未确定但基础档案已补全时，允许用户先使用通用模板生成学习路线

### 异常场景

1. 用户未选目标院校时，允许先用通用模板
2. 用户每日时长过低时，提示备考风险

## 8.7 周计划与日计划

### 功能目标

把长期路线拆到可执行层面。

### 功能说明

1. 系统根据路线生成周计划
2. 用户可手动调整周计划
3. 周计划可拆解为日计划

### 周计划字段

1. 周起止日期
2. 科目任务列表
3. 建议学习时长
4. 优先级
5. 完成状态

### 日计划字段

1. 日期
2. Todo 列表
3. 预计学习时长
4. 实际完成情况

### 业务规则

1. 用户可新增、编辑、删除计划项
2. 超期未完成任务允许延后或放弃
3. 当日计划应同步到首页
4. 首次生成学习路线时，系统默认只生成当前周计划及当前周对应的日计划，后续周次按需展开

### 异常场景

1. 无计划时提示创建或使用模板
2. 删除包含 Todo 的计划时需二次确认

3. 无打卡数据时展示鼓励型空态

### 异常场景

1. 用户重复打卡时提示编辑当日记录
2. 时长超出合理范围时提示确认

## 9. 用户故事

1. 作为刚决定考研的用户，我希望通过学校和专业筛选快速找到感兴趣的院校，以便缩小选择范围。
2. 作为正在比较多个目标方向的用户，我希望收藏并对比多个专业项的分数线和报录比，以便做出更稳妥的择校决策。
3. 作为已经确定目标的用户，我希望设置目标院校并自动生成备考路线，以便把长期目标落地。
4. 作为执行力不足的用户，我希望系统把计划拆成周计划和 Todo，以便我每天知道该做什么。
5. 作为坚持备考的用户，我希望每天打卡并看到学习统计，以便获得反馈和成就感。
6. 作为资源筛选困难的用户，我希望看到按阶段整理的资料推荐，以便减少无效搜索。

1. 学校数据录入与编辑
2. 专业数据录入与编辑
3. 年份数据维护
4. 资料内容管理
5. 来源链接维护
6. 用户反馈查看

## 12. 非功能需求

### 12.1 性能

1. 常规页面首屏加载应尽量控制在可接受范围
2. 列表页需支持分页或懒加载
3. 常用页面需支持本地缓存最近访问数据

### 12.2 可用性

1. 空态、异常态、无数据态必须明确
2. 数据字段缺失必须有清晰标识
3. 新用户第一次进入规划模块时需有引导

### 12.3 合规

1. 展示数据应保留来源
2. 页面中明确“以官方最新公告为准”
3. 不直接提供侵权学习资源下载
4. 登录与通知权限遵循最小必要原则

## 13. 验收标准

### 13.1 产品验收

1. 用户可以完成从注册到目标设置的完整流程
2. 用户可以检索、筛选、收藏并对比专业项
3. 用户可以查看院校详情中的核心择校数据
4. 用户可以生成基础学习路线并编辑计划
5. 用户可以创建 Todo 并完成打卡
6. 用户可以查看资料推荐和关键提醒

### 13.2 数据验收

1. 所有核心院校字段均有来源标记或缺失标记
2. 关键展示数据具备年份维度
3. 资料推荐有来源说明和适用阶段说明

### 13.3 体验验收

1. 主流程不出现无法返回或死路页面
2. 空态、错误态文案完整
3. 首次使用能在较短路径内完成核心闭环

## 14. 风险与待确认事项

### 当前已知风险

1. 院校数据采集和维护成本高
2. 数据年份口径不统一可能影响对比体验
3. 网课和资料推荐存在版权与失效风险
4. 学习路线模板如果过于粗糙，可能降低用户信任

### 待确认事项

1. 登录是否只做手机号，还是预留微信登录
2. MVP 首批覆盖多少学校和专业
3. 学习路线模板按通用考研模板，还是按学科细分
4. 提醒节点是否按全国统一模板，还是按用户目标院校差异化
