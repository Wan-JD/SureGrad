# 一研为定 Android App 项目计划书

版本：`v0.1`

日期：`2026-05-16`

适用阶段：`项目起步 / 立项 / 方案设计`

## 1. 项目概述

### 1.1 项目背景

考研用户在备考过程中通常面临三类核心问题：

1. 信息分散：院校、专业、分数线、报录比、复录比、参考书目、招生简章、考试科目等信息散落在各高校官网、经验贴、公众号和培训机构内容中，搜集成本高。
2. 决策困难：用户很难基于自身基础、目标院校难度、时间投入和竞争情况做出合理择校判断。
3. 执行断裂：即使确定目标，很多考生也缺少完整的学习路线、阶段目标、日程管理和长期坚持机制。

本项目拟打造一款面向考研学子的 Android App，通过“择校信息平台 + 学习规划工具 + 资料推荐系统”三位一体的方式，帮助用户从“选学校”走到“真正考上”。

### 1.2 项目愿景

成为考研用户从择校、备考到复试全周期使用的移动端助手。

### 1.3 核心定位

不是单纯的“资讯 App”，也不是单纯的“Todo 工具”。

本产品的核心定位是：

`以考研决策为入口，以学习执行为抓手，以长期陪伴为价值的备考平台。`

## 2. 用户分析

### 2.1 目标用户

主要面向以下三类用户：

1. 大三 / 大四准备考研的本科生
2. 二战、三战考生
3. 在职备考用户

### 2.2 用户画像

#### 用户画像 A：信息焦虑型

- 刚决定考研，不知道如何选学校和专业
- 关注“我能不能考上”
- 需要院校难度、分数线、报录比、复录比、竞争强度等数据支持

#### 用户画像 B：执行拖延型

- 有目标院校，但学习缺少节奏
- 容易计划很多、执行很少
- 需要路线图、日程安排、Todo、打卡和提醒机制

#### 用户画像 C：资源筛选型

- 知道要学什么，但不知道跟谁学、看什么资料
- 容易陷入“网课太多不会选”
- 需要课程推荐、资料清单、公开资源链接和阶段化学习建议

### 2.3 核心痛点

1. 院校信息难收集、难对比、更新不稳定
2. 难以把“择校决策”转化成“备考行动”
3. 学习规划缺少个性化和阶段化
4. Todo 工具很多，但没有贴合考研场景
5. 资料很多，但真假难辨、质量参差不齐

## 3. 产品目标

### 3.1 业务目标

1. 建立考研院校与专业信息数据库
2. 打造高频使用的学习规划与执行工具
3. 形成“信息查询 + 规划执行 + 内容推荐”的用户闭环
4. 为后续会员、增值服务、训练营、咨询服务预留商业化空间

### 3.2 用户目标

1. 帮用户更快完成择校与择专业决策
2. 帮用户获得更清晰的学习路线和阶段目标
3. 帮用户持续执行每日学习任务
4. 帮用户降低信息焦虑，提高备考效率

### 3.3 成功指标

建议在 MVP 和首个正式版本中重点关注以下指标：

1. 新用户 3 日留存
2. 学习计划创建率
3. 日活用户中 Todo 完成率
4. 院校详情页访问深度
5. 收藏院校 / 收藏资料 / 订阅提醒转化率
6. 周活跃用户中连续打卡率

## 4. 产品价值主张

### 4.1 对用户的直接价值

1. 用更低时间成本找到适合自己的学校和专业
2. 用更清晰的计划推进全年备考
3. 用更可信的资源减少试错
4. 用更稳定的工具保持执行力

### 4.2 相比常见竞品的差异化方向

可重点走以下差异化路线：

1. `数据化择校`
2. `备考执行工具化`
3. `学习资料正规化、可筛选`
4. `全年路线模板化`
5. `考研场景深度适配，而不是通用任务管理`

## 5. 功能全景设计

## 5.1 一级模块

建议规划为 6 大模块：

1. 首页
2. 择校库
3. 学习规划
4. 资料推荐
5. 学习工具
6. 我的

### 5.2 模块说明

#### 模块 A：首页

作用：承接用户进入 App 后的高频操作。

建议内容：

1. 今日学习概览
2. 今日待办
3. 学习时长统计
4. 推荐院校 / 推荐资料
5. 备考阶段提示
6. 近期重要时间节点提醒

#### 模块 B：择校库

这是本产品的核心竞争力模块，应优先建设。

建议能力：

1. 全国院校列表
2. 按地区、院校层次、专业门类、学硕专硕筛选
3. 院校详情页
4. 专业详情页
5. 历年分数线
6. 报录比
7. 复录比
8. 推免比例
9. 招生人数变化
10. 初试科目与参考书目
11. 学费、学制、住宿、城市成本等辅助决策信息
12. 收藏院校
13. 多院校对比
14. 订阅院校信息更新提醒

院校详情页建议包含：

1. 基础信息：学校、城市、院系、专业、学制、学费
2. 招生信息：招生人数、推免人数、统考名额
3. 竞争信息：分数线、报录比、复录比、复试权重
4. 考试信息：考试科目、参考书、专业课说明
5. 经验信息：备考建议、常见问题、注意事项
6. 官方入口：招生简章、专业目录、复试方案、官网链接

#### 模块 C：学习规划

该模块负责把“目标院校”转化为“执行计划”。

建议能力：

1. 目标设定：目标院校、目标专业、目标分数
2. 备考起点测评：基础水平、剩余备考时间、每天可投入时长
3. 学习路线生成：全年路线、阶段目标、月计划、周计划
4. 模板计划：基础薄弱版、跨考版、二战版、在职版
5. 科目进度管理：政治、英语、数学、专业课分科管理
6. 阶段性复盘
7. 偏科预警
8. 冲刺阶段提醒

建议规划方式：

1. 长期目标：全年备考路线
2. 中期目标：月度 / 阶段目标
3. 短期目标：周计划 / 日计划
4. 执行层：Todo 任务拆解

#### 模块 D：资料推荐

该模块重点在“高质量、合法、可筛选”。

建议能力：

1. 网课推荐
2. 公开课程网址收录
3. 参考书清单
4. 真题资料说明
5. 学习资料分类导航
6. 按学科和阶段推荐资料
7. 收藏资料
8. 资料评分和标签

资料推荐的基本原则：

1. 优先推荐公开合法资源
2. 不直接触碰侵权资料分发
3. 资料页以“来源链接 + 内容说明 + 适用阶段 + 用户评价”形式呈现

#### 模块 E：学习工具

这是提升用户粘性的关键模块。

建议能力：

1. Todo 清单
2. 日程安排
3. 学习打卡
4. 番茄钟
5. 学习时长统计
6. 倒计时
7. 习惯养成
8. 专注模式
9. 错题 / 易错点记录
10. 模拟成绩记录

#### 模块 F：我的

建议能力：

1. 账号信息
2. 我的目标院校
3. 我的学习计划
4. 我的收藏
5. 我的学习统计
6. 提醒设置
7. 反馈中心
8. 会员中心

## 6. 可以发散增加的高价值功能

以下功能不必全部进入 MVP，但很有实际意义：

1. `智能择校推荐`
基于用户本科背景、目标城市、分数预估、竞争偏好，推荐可冲 / 可稳 / 可保院校。

2. `院校对比雷达图`
将分数线、报录比、复录比、城市吸引力、学费、就业去向等可视化。

3. `关键节点提醒`
如预报名、正式报名、现场确认、打印准考证、初试、查分、复试、调剂等。

4. `复试专区`
包括复试流程、材料准备、常见问答、英语面试准备、联系导师建议。

5. `调剂信息专区`
适合在后期版本增加，提升用户在初试后的继续使用价值。

6. `AI 学习助手`
可用于计划生成、阶段复盘、学习答疑、英语作文批改、政治背诵提醒等。

7. `备考社区`
建议谨慎上线，社区审核成本高，适合后期版本。

8. `学习数据周报`
按周输出学习时长、任务完成率、偏科情况和下周建议。

9. `目标院校资讯订阅`
当院校简章、目录、复试方案更新时提醒用户。

10. `备考心态支持`
例如鼓励文案、复盘模板、情绪记录，这类功能对留存有帮助。

## 7. MVP 范围建议

项目起步阶段不建议功能一上来做得过大。建议先做一个可用、可验证、可积累数据的 MVP。

### 7.1 MVP 必做功能

1. 用户登录与基础档案
2. 院校 / 专业信息查询
3. 分数线、报录比、复录比等核心数据展示
4. 院校收藏与对比
5. 目标设定
6. 学习路线模板
7. 日计划 / 周计划
8. Todo 清单
9. 打卡与学习统计
10. 资料推荐列表
11. 重要节点提醒

### 7.2 MVP 暂缓功能

1. 社区
2. 即时聊天
3. 大规模 AI 生成能力
4. 调剂专区
5. 深度商城 / 付费电商

### 7.3 MVP 核心闭环

建议围绕下面这条主路径设计：

`查院校 -> 收藏对比 -> 设定目标 -> 生成备考路线 -> 拆解周计划 / Todo -> 打卡执行 -> 复盘调整`

只要这个闭环成立，产品就具备初期验证价值。

择校库是本产品的地基，建议从一开始就重视数据结构。

### 9.1 核心数据实体

1. 学校
2. 院系
3. 专业
4. 年份维度招生数据
5. 分数线数据
6. 报录比数据
7. 复录比数据
8. 考试科目
9. 参考书
10. 官方通知链接
11. 学习资料
12. 用户计划
13. 用户任务
14. 用户学习记录

### 9.2 数据来源建议

优先级建议如下：

1. 高校研究生院官网
2. 招生简章与专业目录
3. 复试录取办法
4. 教育主管部门公开信息
5. 公开、合法的第三方资料作为补充

### 9.3 数据建设原则

1. 官方信息优先
2. 每条关键数据保留来源链接
3. 数据更新时间可见
4. 对“缺失数据”和“非官方估算数据”明确标注
5. 后台支持人工校正

## 10. 技术方案建议

## 10.1 技术路线推荐

若以“小团队快速落地 + 后续可扩展”为目标，建议采用：

1. App 端：`Flutter`
2. 后端：`NestJS`
3. 管理后台：`Next.js + Ant Design`
4. 数据库：`PostgreSQL`
5. 缓存：`Redis`
6. 对象存储：`MinIO` 或云 OSS
7. 搜索：MVP 可先用数据库检索，后续升级为 `Meilisearch` 或 Elasticsearch

选择依据：

1. Flutter 适合快速迭代移动端界面，后续如需 iOS 扩展成本较低
2. NestJS 对内容型和数据型中后台项目足够高效
3. PostgreSQL 适合结构化数据和筛选查询
4. 后台系统对数据运营和人工修订非常关键

### 10.2 系统组成

建议按 4 个子系统规划：

1. Android App
2. 后端 API 服务
3. 管理后台
4. 数据采集与入库工具

### 10.3 核心后端模块

1. 用户中心
2. 院校数据中心
3. 计划与任务中心
4. 资料中心
5. 提醒中心
6. 统计分析中心
7. 管理后台权限中心

### 10.4 客户端重点能力

1. 账号登录
2. 本地缓存
3. 离线查看最近内容
4. 推送通知
5. 图表展示
6. 学习打卡和本地状态同步

## 11. 合规与风险

这个项目一定要尽早考虑合规问题。

### 11.1 数据合规风险

1. 采集高校公开信息时要控制频率并保留来源
2. 不建议未经授权大规模抓取受限制页面
3. 对转载内容、经验帖和第三方数据要明确来源

### 11.2 内容版权风险

1. 网课推荐应以课程链接和介绍为主
2. 不直接提供侵权盗版资料下载
3. 对参考书封面、课程内容、讲义资源要注意版权归属

### 11.3 隐私合规风险

1. 用户学习数据、手机号、账号信息要做隐私保护
2. 上线前需要准备隐私政策和用户协议
3. 通知权限、存储权限等要按最小必要原则申请

### 11.4 信息准确性风险

1. 院校数据易变动
2. 分数线和招生计划存在年份差异
3. 需要在页面中明确“以官方最新公告为准”

## 12. 商业化方向建议

项目初期先做用户价值，商业化可以后置，但建议一开始就预留结构。

可行方向：

1. 会员功能
2. 高级择校分析报告
3. 个性化学习规划
4. 一对一咨询服务
5. 合法课程推广分佣
6. 复试 / 调剂专题服务

不建议初期就做重销售导向，否则会影响产品信任感。

3. 后端开发
4. UI/UX 设计

5. 数据录入与校验由运营承担

## 15. 当前阶段最重要的决策

项目起步期，最重要的不是“把所有功能都想全”，而是先做对下面 5 件事：

1. 选定明确的 MVP 范围
2. 确定院校数据模型
3. 明确资料推荐的合规边界
4. 搭好“择校 -> 规划 -> 执行”的闭环
5. 优先完成后台数据维护能力

如果这 5 件事没做好，后续开发会反复返工。

## 17. 结论

这个项目具备较强现实需求，尤其适合在中国考研市场做“高频工具 + 决策信息”结合型产品。

从产品逻辑上看，最值得优先做强的并不是“资讯流”，而是以下两点：

1. 院校与专业数据能力
2. 学习规划与执行能力

建议项目初期坚定围绕 `择校决策 + 学习执行` 两条主线推进，资料推荐作为增强模块逐步补齐。这样既能形成差异化，也更容易做出真正有粘性的产品。
